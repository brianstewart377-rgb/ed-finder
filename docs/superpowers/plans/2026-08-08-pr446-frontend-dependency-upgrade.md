# PR #446 Frontend Dependency Upgrade (minus Tailwind) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land every dependency bump from Dependabot PR #446 except Tailwind CSS (and its directly-coupled PostCSS plugin), on a fresh branch, in three risk-tiered commits, each independently verified.

**Architecture:** Three sequential commits on branch `chore/pr446-frontend-deps-minus-tailwind` (already created, currently holds only the design-spec commit). Each commit bumps a risk-tiered subset of `frontend/package.json`, regenerates `frontend/yarn.lock` via `yarn install`, and is verified before moving to the next. A final task runs full CI-equivalent verification plus a manual `yarn dev` smoke check, then opens the PR and closes #446.

**Tech Stack:** Yarn 1.22 (classic), Vite, Vitest, TypeScript, ESLint flat config, React 19.

## Global Constraints

- Do NOT change `tailwindcss`, or any Tailwind-specific PostCSS wiring. `tailwindcss` stays pinned at `^3.4.18` in `frontend/package.json` for the whole plan.
- `autoprefixer` and `postcss` bumps ARE included (they're independent of Tailwind's major version, not part of the v4 migration surface).
- Every `yarn install` must be run from `frontend/` and must NOT use `--frozen-lockfile` (we're intentionally changing the lockfile in this plan).
- Every verification command in this plan must be run from `frontend/` unless stated otherwise.
- Node in this environment must be v22+ (already the case after PR #451 bumped CI; if a local shell reports Node 20.x, `yarn install` will fail on `jsdom` — confirm with `node --version` before starting if unsure).
- Commit messages: plain, descriptive, no marketing language, matching this repo's existing commit style (see `git log --oneline -10` for tone).
- Do not touch `recharts` or `vite-plugin-pwa` usage sites — they have zero call sites in `src/`; only their `package.json` version pins change.
