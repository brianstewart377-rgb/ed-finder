1. Pure mapping, raven-apply.ts. Export
   `ravenToPlannerModel(result: RavenImportResult, data: PlanBodiesV1): { model: PlannerModel; warnings: { code: string; detail: string }[] }`
   (throw only if `result.ok` is false or `result.system.id64 !== data.system_id64`; the page checks both first).
   - Locations come from `resolvePlanLocations(data)` only. A site or slot row may end up only on one of those `body_ref`s, or Unplaced (`body_ref: null`).
   - Belts first: if a Raven body name is exactly a belt's name, or is `<belt name> Cluster <digits>`, map it to that belt's location `body_ref`. This covers clusters that are hidden in ED-Finder and clusters missing from ED-Finder's data. If the cluster number is not the lowest that ED-Finder has for that belt (or ED-Finder has none), add warning `belt_cluster_moved` naming the Raven body and the belt. The game builds belts only through the first cluster.
   - Otherwise match with `matchRavenBodies` (exact name, case-insensitive, trimmed) and keep the warnings it gives. A match that is not a visible location (a barycentre, or anything `resolvePlanLocations` hides) becomes Unplaced with warning `hidden_body`.
   - Unmatched or ambiguous names become Unplaced. Carry the warnings from `matchRavenBodies`.
   - Sites keep Raven's order. Use status, facility_id, slot_kind and name from the parse result. Each site gets `schema: 'cpe_site_v1'` and a deterministic `site_id` derived from `raven_site_id`, valid under `isPlannerSite`. If an id is reused or invalid, derive a unique id and warn `site_id_changed`. Every produced site must pass `isPlannerSite`. If more than `MAX_SITES` sites remain, keep the first `MAX_SITES` and warn `too_many_sites`.
   - If a facility does not fit its location (`facilityFitsLocation` needs the facility; if the page's facility list is not available to this pure function, take an optional facilities argument), keep the site where Raven put it and warn `facility_location_mismatch`. The evaluator will show it as Blocked with a reason.
   - Slots: give each mapped location `{orbital_slots, surface_slots}` from its Raven slot row. Several Raven rows can map to one belt. Use the row from the lowest-numbered cluster and warn `belt_slots_merged` for the rest. Drop rows for unmatched or hidden bodies with warning `slots_dropped`. The result must satisfy the model's slot validation (null or an integer from 0 to 64).
   - Deterministic: no Date, no randomness, no I/O. The result must pass `rejectInvalidLocations(model, data)`.

2. Page, PlanWorkspace.svelte. Add an "Import from Raven" button next to "Import plan", with its own hidden file input (accept .json; aria-label "Import Raven Colonial layout file"). Then:
   - Over `MAX_IMPORT_BYTES` → the existing action-error message style.
   - JSON.parse failure → "This file is not a Raven Colonial layout (it is not valid JSON)."
   - `parseRavenLayout` not ok → show its first error detail.
   - Bodies not loaded → the same "Wait for the system bodies to load…" error as the existing import.
   - `system.id64` differs → refuse, with no confirm: "This Raven layout is for <name> (<id64>). Open that system's planner to import it."
   - Otherwise build the model and confirm with `window.confirm`: "Replace this system's planner sites and slot counts with <n> sites from Raven Colonial? <u> will be Unplaced and <w> items need checking. The first site becomes the Primary Port." Then apply through `change((current) => replacePlan(current, candidate))`, exactly like the existing import, so the Primary Port protection (RB-0008) is enforced. Show its error if it refuses.
   - After a successful import, announce it in the page's existing polite live region: "<n> sites imported from Raven Colonial." Show the warnings as a dismissible list ("Import notes (<w>)") near the header. Use a `<details>` element or the existing disclosure pattern, each warning's detail as a list item, and a Dismiss button. No colour-only meaning.
   - Never print or store the file's raw contents beyond what the model keeps. Keep the existing "Import plan" behaviour exactly as it is.
